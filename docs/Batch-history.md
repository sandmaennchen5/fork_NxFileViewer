# Batch history and resume

The batch page offers recent sessions (default 5, configurable from 1 to 100 under Settings → Program → History), with date, source path, result count and state. **Show** displays the recorded results without starting a task. **Resume** rereads the source and processes pending, changed or failed entries. New files are included. Completed entries are skipped only when their size and last-write timestamp still match, and the missing-delta-fragment verification policy is unchanged.

Archive entries use the parent ZIP/7z file's size and timestamp. Firmware folders use the sorted file list, names, sizes and timestamps. Fingerprints are captured before and after processing; a source changed during processing cannot be skipped on resume. This is a metadata change check, not an additional cryptographic hash check. A cancelled integrity check resumes verification; a cancelled metadata scan resumes scanning.

History is written atomically to `History/batch-integrity.json` beside the executable, at most once a second during result callbacks and again when a run finishes or is cancelled. Unexpected termination may lose the last second of completed results; those files are checked again. The configured number of most recent distinct runs is retained, and resuming updates the same run. Lowering the limit restricts the displayed list immediately; older entries are removed from the history file on the next checkpoint/session save. Increasing the limit cannot recover entries already removed. Historical results include file/package/security metadata, localized title/publisher texts and firmware details, not decrypted content, key values or logos. Full file overview objects are not persisted. The historical game overview uses the normal file/package layout without reopening files or archives, including package and language selection where saved. A history notice replaces the logo. Older sessions show only the metadata available in their original records; explicitly rereading their source is required to capture new fields. Loading a session selects its first visible result; active scans follow the current game package automatically.

Dropped selections can include multiple files, folders and archives. Their source list is saved and restored for resume; overlapping sources do not create duplicate results. Merely selecting a historical row never reloads its source, regardless of automatic-verification settings.

The program directory must be writable. There is no AppData fallback. History errors are logged and do not abort the check. Missing source directories cannot be resumed, but their saved results can still be displayed. History states: Running, Interrupted, Completed (completion of processing does not mean all files passed).
History can be disabled under Settings → Program. This hides history controls and stops checkpoint reads/writes; existing files remain available after enabling it again. The preference is saved in the application settings JSON file and defaults to enabled.
