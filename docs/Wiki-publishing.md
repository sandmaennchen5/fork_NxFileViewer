# Publishing the documentation as a GitHub wiki

The documentation remains maintained in this application repository. The exporter
creates an additional wiki copy with Home, sidebar and footer pages. It converts
local Markdown links to wiki pages and links screenshots and source/configuration
files back to this repository.

## Export locally

From the application repository root:

```powershell
python -B .github/scripts/export_wiki.py
```

The default output is the sibling directory **fork_NxFileViewer.wiki**.
This is an export folder, not automatically a Git checkout. Exporting never
commits, fetches or pushes anything.

Run the same command again after editing the source docs. Only previously generated
pages are updated/removed; unrelated custom pages and .git are retained.
A first export refuses to overwrite existing pages with matching names. Use
--overwrite only when you intend to replace those generated page names.

## Publish through the separate wiki repository

GitHub wikis use a separate repository:

```text
https://github.com/sandmaennchen5/fork_NxFileViewer.wiki.git
```

Enable Wiki and create/save its first page on GitHub if it has not been initialized.
Then clone it into an **empty** directory. If the default export folder already
exists without .git, keep that preview and use a different empty checkout folder:

```powershell
git clone https://github.com/sandmaennchen5/fork_NxFileViewer.wiki.git ../fork_NxFileViewer.wiki-publish
python -B .github/scripts/export_wiki.py --output ../fork_NxFileViewer.wiki-publish --overwrite
cd ../fork_NxFileViewer.wiki-publish
git status
git add .
git commit -m "Update documentation wiki"
git push origin HEAD
```

You can instead use fork_NxFileViewer.wiki as the clone destination when it is
empty, then export there with the default command. Clone before exporting to
retain any existing remote history. Do not force-push an independently initialized
local repository over an existing wiki.

For an existing checkout, pull its default branch before exporting. Only pushes to
the wiki's default branch become public wiki pages. The first --overwrite replaces
the initial Home page and any other names generated by the exporter; pages with
other names remain untouched.

Source code/JSON links and screenshots use master by default. To preview another
published branch or repository, use --ref and --repository. The exporter does not
copy private local settings, keys or runtime data.

See [GitHub's wiki editing documentation](https://docs.github.com/en/communities/documenting-your-project-with-wikis/adding-or-editing-wiki-pages).

## German pages: wiki only

The application repository keeps its documentation in English. Additional German
topic guides are maintained exclusively in the wiki repository in
`.nxfileviewer-wiki-de.json`. The German guides are condensed instructions; the
full English technical reference remains available through each language switch.

The exporter reads that file from the output folder and adds DE-prefixed pages,
English/Deutsch switches and bilingual navigation. Translation entries contain
the English page key, a German title and Markdown content. Relative links are
resolved as if the text came from the corresponding English source file; links
to translated topics automatically select the German page. Topics without a
translation keep their English destination.

The JSON source is not itself a wiki page. Commit it together with the generated
Markdown and ownership manifest so another clone can reproduce both languages.
When exporting into a different first-time clone, pass the existing translation file:

```powershell
python -B .github/scripts/export_wiki.py --output ../fork_NxFileViewer.wiki-publish --german-source ../fork_NxFileViewer.wiki/.nxfileviewer-wiki-de.json --overwrite
```

Also copy the translation JSON into that checkout before committing it. Subsequent
exports find it automatically. A missing German source never silently deletes
previously generated German pages.

German entries may record the normalized English source SHA-256 as sourceSha256.
When that source changes, the German page displays an outdated-translation notice.
Update the German content and source hash after review. This is not automatic
machine translation and requires no translation API or key.
